## 节点与产物

`$ARGUMENTS` 是调用方提供的节点标签，可以是任意节点名称，不设封闭枚举。若未提供标签，从当前触发的 `after_*` 钩子和刚完成的节点上下文识别。不要因节点名是新增的或未知的而拒绝；必须确认当前节点成功完成，并从本次节点输出与会话执行记录确定产物文件。节点类型或本次产物无法可靠判定时，停止并说明原因。

本命令提交当前节点实际生成或修改的所有产物，包括代码、测试、文档及必要配置。范围由本次节点的输出清单和当前会话中的编辑记录确定，不用固定节点/路径清单代替判断。

## 提交步骤

1. 检查当前分支和工作区状态。若索引已有暂存内容，停止并说明原因；不要修改现有暂存内容。
2. 对照当前节点的实际输出、会话编辑记录与 Git 差异，列出本节点确实新建或修改的路径。不得仅凭文件存在、同一目录或“都属于本功能”推断文件归属。
3. 排除节点开始前已存在的用户改动及与本节点无关的变更。若某路径的差异无法可靠归属于本节点，停止提交并说明涉及路径；不要提交整文件或扩大范围。若没有本节点产物变更，报告无变更，不创建空提交。
4. 只暂存明确属于本节点的路径，使用 `git add -- <明确路径>`；不得使用 `git add .` 或 `git add -A`。
5. 检查暂存文件清单和差异，确认只包含本节点产物。若含其他文件或无法确定来源，不提交；不要清理或重置暂存区。
6. 根据实际产物选择提交类型，例如 `feat`、`fix`、`docs` 或 `chore`，创建一个本地提交，格式为 `<类型>(speckit): <节点> <简要说明>`。每次只提交当前节点产物，不合并其他节点内容。不 push、不 amend。
7. 用 `git log -1 --oneline` 确认提交，并报告摘要。若暂存、提交或验证失败，如实报告，不声称成功。

所有 Git 命令前缀必须包含 `GIT_MASTER=1`。本命令不创建、删除或切换分支，也不运行脚本代替 AI 判断提交范围。
